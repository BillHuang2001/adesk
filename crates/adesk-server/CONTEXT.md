# adesk-server — runtime binary + AGP server

## Intent

`adesk-server` is the composition root of the ADesk runtime and the only process an agent ever talks to.
It starts the compositor thread, binds the AGP Unix socket and (when enabled) the viewer's VAP v1 endpoint, pumps `RuntimeEvent`s into the observer and the subscription fan-out, and serves every method of `docs/protocol.md` §5 plus the Viewer Attachment Protocol of `docs/viewer.md`.
It owns the process-lifetime concerns no sibling can own: the socket files, the action→observation wiring, subscription fan-out, signal handling and the ordered shutdown sequence.
It also owns every conversion between sibling crates' overlapping types (`src/translate.rs`), because no sibling depends on another.

Every module is implemented (`src/` has no `todo!()`); `cargo test -p adesk-server` is green — 221 tests across lib, bin and the ten integration targets (145 lib + 9 bin + 67 integration), 0 failed, 0 ignored.

## API Surface

Everything below is re-exported at the crate root; `adesk-testkit` is designed against exactly this surface.

- `ServerConfig { socket_path: PathBuf, compositor: CompositorConfig, app_dirs: Option<Vec<PathBuf>>, viewer: ViewerConfig }` (`src/config.rs`)
  - `new(socket_path, compositor)` (the constructor `adesk-testkit`'s harness calls) and `Default` (environment-resolved socket path, compositor defaults); builders `with_socket_path`, `with_output_size`, `with_renderer`, `with_xkb`, `with_app_dirs`; `socket_path()`.
  - `viewer: ViewerConfig { enabled: bool (default true), socket_path: Option<PathBuf> (None = derive), tcp: Option<SocketAddr> (None = off) }` — the viewer (VAP v1) endpoint configuration; builders `with_viewer`, `with_viewer_socket`, `with_viewer_tcp`, `without_viewer`.
  - `viewer_socket_path(&self) -> Option<PathBuf>`: `None` when the endpoint is disabled, else the explicit override, else `viewer_socket_sibling(&self.socket_path)` — a free fn deriving the sibling of the AGP socket (stem gains `-viewer`, directory and extension kept: `…/adesk.sock` → `…/adesk-viewer.sock`). `config.rs` never reads `$ADESK_VIEWER_SOCKET`; clap owns it, so the precedence is `--viewer-socket` > `$ADESK_VIEWER_SOCKET` > derived sibling.
  - `default_socket_path()` resolves `$ADESK_SOCKET` → `$XDG_RUNTIME_DIR/adesk.sock` → `<temp_dir>/adesk.sock` (`std::env::temp_dir()` honours `$TMPDIR`); `adesk_client::default_socket_path()` uses the identical chain.
  - `parse_size("WxH")` / `parse_renderer("auto|gl|pixman")` are the CLI value parsers.
- `adesk-server` binary flags (`src/main.rs`, clap derive on `Cli`), every flag carrying an `ADESK_*` env fallback (`clap`'s `env`): `--socket <PATH>`/`ADESK_SOCKET`, `--output <WxH>`/`ADESK_OUTPUT`, `--renderer <KIND>`/`ADESK_RENDERER`, `--xkb-layout|--xkb-variant|--xkb-model|--xkb-rules`/`ADESK_XKB_*`, `--apps-dir <DIR>` (repeatable, `:`-separated in `ADESK_APPS_DIR`), `--log <FILTER>`/`ADESK_LOG` (default `info`, invalid directives fall back to `info`); plus clap's `--help` and `--version` (`CARGO_PKG_VERSION`). `build_config` starts from `ServerConfig::default()` and applies only the flags that are set, so unset flags keep the environment-resolved defaults.
  - Viewer flags: `--viewer-socket <PATH>`/`ADESK_VIEWER_SOCKET`, `--viewer-tcp <HOST:PORT>`/`ADESK_VIEWER_TCP` (opt-in second transport, parsed by `parse_socket_addr`), `--no-viewer` (bool, no env; wins over both).
- `adesk_viewer::ViewerBackend` for the runtime (`./src/viewer/backend.rs`, `pub(crate) ViewerBackendImpl`): `display` (`ServerHello`), `render_frame`, `desktop_state`, `apply_input` (returns the recorded `ActionId`; the `ViewerInput::ActivateWindow` arm reuses `dispatch::windows::activate_window` — runtime-native, ordered through the shared `InputQueue` — and every backend failure keeps its AGP `ErrorCode` on the wire), `change_signal`, `set_control`.
- `Server::start(ServerConfig) -> Result<RunningServer, ServerError>` — **async** (`src/server.rs`).
- `RunningServer` (Clone handle; `Debug` prints only the socket path; dropping it does not stop the runtime):
  - `socket_path() -> &Path`, `viewer_socket_path() -> Option<&Path>` (the bound VAP v1 Unix socket, `None` when the endpoint is disabled), `compositor() -> &CompositorHandle`, `observer() -> &ObserverService`, `registry() -> &Arc<AppRegistry>`, `context() -> &ServerContext`, `shutdown_handle() -> &ShutdownHandle`;
  - `async wait() -> Result<()>` (resolves when the runtime stops serving), `async shutdown() -> Result<()>` (idempotent).
- `ServerContext` (`src/context.rs`): cheap-clone bundle with public fields `config`, `compositor`, `observer`, `registry`, `correlator`, `subscriptions`, `inspect_subscriptions`, `inspection`, `cursor`, `shutdown`, `started_at`; `now_ms()`, `uptime_ms()`, `next_connection_id()`.
- `CursorTracker { set(Point), get() -> Option<Point> }` — last commanded pointer position (the compositor snapshot has no cursor).
- `ShutdownHandle` (`src/shutdown.rs`): `new()`, `initiate() -> bool`, `is_shutting_down()`, `async cancelled()`; `install_signal_handlers`, `run`, `remove_socket_file`.
- `SubscriptionRegistry` / `InspectRegistry` (`src/subscriptions.rs`): thin wrappers over one private generic `Registry<T>` (with a private `RegistryEntry` trait) that owns the shared storage, id allocation and lock discipline; public methods `subscribe`, `unsubscribe`, `remove_connection`, `fan_out`/`list`, `len`, `is_empty`; `InspectRegistry` additionally exposes `pub(crate) contains(SubscriptionId) -> bool` and `pub(crate) prune_closed() -> usize`, both locking and scanning without cloning payloads; `SubscriptionId = u64`, `EventSink = mpsc::Sender<Frame>`.
- `InspectionCache` (`src/inspection.rs`): implements `adesk_inspector::InspectionSource` over a cached `InspectionSnapshot`; `store`, `snapshot`, async `refresh(&ServerContext)`.
- `ServerError` (`src/error.rs`) with `code() -> ErrorCode` / `payload() -> ErrorPayload`, and the crate alias `Result<T, E = ServerError>` — `Result<T>` and `Result<T, ServerError>` are both valid spellings (startup/bind paths name the error explicitly).
- `SocketListener::bind(&Path)`, `prepare_socket_path`, `Connection::new/run`, `ConnectionWriter::send/try_send`, `Dispatcher::new/dispatch`, `Session`/`InputQueue`, `event_pump::spawn/handle_event/resync`, `images::encode/encode_png`.
- `dispatch::command` (`src/dispatch/command.rs`, `pub(crate)`): `send_infallible`/`send_result` — the shared "build `RuntimeCommand` + `oneshot` reply + send + await + classify" seam used by `windows.rs`/`capture.rs`/`input.rs`; a dropped reply is classified by a caller-supplied closure.
- `PROTOCOL_VERSION: u32 = adesk_proto::PROTOCOL_VERSION`, `RUNTIME_VERSION: &str = env!("CARGO_PKG_VERSION")`.

## Lifecycle

Startup (`Server::start`, `docs/architecture.md` §9):
1. `adesk_compositor::spawn(CompositorConfig)` (sync, spawns the calloop thread) → `wait_ready()`.
2. Build `AppRegistry` (`RegistryOptions` from `app_dirs`, one `Arc<dyn Clock>` shared with `Correlator`) and `scan()` (blocking → `spawn_blocking`).
3. Bind the Unix socket (`prepare_socket_path` + `SocketListener::bind`).
4. Spawn the event pump (observer + fan-out + `QueryState` resync).
5. Bind the viewer (VAP v1) endpoint when it is enabled (`crate::viewer::start`: the Unix socket plus the opt-in TCP listener) and spawn its accept loops — before `Server::start` returns, so a returned `RunningServer` means VAP accepts connections too.
6. Install SIGINT/SIGTERM handlers and spawn the AGP accept loop; return `RunningServer` once both listeners are bound.

Shutdown (`RunningServer::shutdown` / signal → `shutdown::run`), in order:
1. `ShutdownHandle::initiate()` — stop accepting.
2. Fail in-flight requests with `shutting_down`; drain connection tasks.
3. `CompositorHandle::shutdown()` — drops the Wayland display (clients lose their connection).
4. Remove the AGP socket file and, when the endpoint is enabled, the viewer socket file; complete `wait()` with `Ok(())`; exit code 0.

## Constraints

- `#![forbid(unsafe_code)]`, `#![deny(missing_docs)]`; files stay far below the ~1000-line threshold.
- No panics on request/event paths: handlers return `ServerError`; the dispatcher converts it to `ErrorPayload` and keeps the connection open.
- The connection closes **only** for framing/protocol corruption — invalid UTF-8, JSON with no usable `u64` id, or a non-request frame from the client; a decode failure that still names a request (unknown method, params that fail validation) is answered with the code it maps to (`unknown_method`, `invalid_request`) and the connection stays open — every request gets exactly one response.
- Input methods (§5.5) allocate an `ActionId` via `ObserverService::record_action` **before** sending compositor commands and run through `Session::input()` so they execute in submission order per connection.
- `activate_window` / `close_window` are runtime-native: they change compositor state directly, never synthesize input.
- Observation methods await the observer first, then render; a wait timeout is an `Observation` with `timed_out: true`, never an error.
- Rendering is on demand: `RenderWindow`/`RenderOutput` only when pixels are needed; no screenshot loop, no per-event rendering.
- Error mapping: `adesk_observer::Error::UnknownWindow` → `unknown_window`, `UnknownAction` → `invalid_request`; `adesk_app_registry::Error::UnknownApp` → `unknown_app`, `NoExec` → `not_supported`, `InvalidExec`/`TryExecNotFound`/`Spawn` → `launch_failed`, `InvalidEntry`/`Io` → `internal`; inspector `InvalidFrame`/`InvalidRequest` → `invalid_request`, `Render` → `render_failed`; `adesk_compositor::CompositorError::code()` and `adesk_proto::ProtoError::error_code()` are delegated verbatim, so compositor `unknown_window`/`invalid_request`/`render_failed`/`shutting_down` and protocol `unknown_method`/`protocol_version_mismatch`/`invalid_request` reach the wire unchanged; `Io`/`Join`/`Internal` and everything unclassified → `internal`.
- `tracing` only: one span per request (`request{id method}`), one per connection, one per window lifecycle; never log pixel payloads.
- Timestamps are monotonic ms since `ServerContext::started_at`; no wall clock in observations.
- Dependencies: every version comes from the root `[workspace.dependencies]`; no inline versions.
- Only `adesk-server` may write the AGP socket path, the viewer socket path and the process-level signal handlers.
- The viewer endpoint owns no protocol logic: `adesk-viewer-proto` and `adesk-viewer` are used as-is, and `./src/viewer/` only implements `adesk_viewer::ViewerBackend` and binds the transports.
- Viewer input is never a special path: it records an `ActionId` on the observer before the compositor command and calls the same `src/dispatch/input.rs` seat helpers as AGP §5.5, so a viewer click and an agent click are the same code path.
- Only the AGP accept loop runs `crate::shutdown::run`; the viewer accept loops only observe the shutdown token — teardown stays ordered and single-owner.

## Design Decisions

- **`ServerConfig::new(socket_path, compositor)` is a 2-argument constructor; defaults come from `Default`.** The objective pinned the struct, its builders and its default resolution but not the constructor arity; `adesk-testkit`'s harness (designed in parallel) calls `ServerConfig::new(socket_path, compositor).with_app_dirs(..)`, so the server matches the consumer. `Default` keeps the env-resolved socket path and compositor defaults.
- **Dev-dependencies are only what `./tests/` needs** (`adesk-client`, `tempfile`, `futures` for the viewer suite's typed streams, and `adesk-testkit` so `./tests/viewer.rs` can drive a real toplevel — the same dev-dependency cycle `crates/adesk-compositor` already uses). Wire-only AGP cases still go through the suites' own NDJSON `RawClient`, and the in-module unit tests use no test-only crates. `./tests/viewer.rs` is the only local suite that connects a Wayland client.
- **`Server::start` and `RunningServer::wait`/`shutdown` are async.** The objective's signature sketch omitted `async`, but compositor `wait_ready()`/`shutdown()` are async and the server is a tokio process; `adesk-testkit` must `.await` them. `registry() -> &Arc<AppRegistry>` (not `&AppRegistry`) is pinned so tests can clone the handle.
- **One writer task per connection + bounded queue.** The read loop owns decoding/dispatch; a dedicated writer task owns the write half and is fed by an `mpsc::Sender<Frame>` (`ConnectionWriter`). Responses `send().await` (backpressure); subscription events `try_send` (drop, never block the pump). This keeps every request answered exactly once even while events stream.
- **Every undecodable-but-identifiable request is answered inline by the read loop.** `ProtoError` carries no request id, so the read loop lifts it from the raw line and answers through `error_response` with the error's mapped code — `unknown_method` for an unknown method, `invalid_request` for params that fail validation or any other request-shaped decode failure (§1/§6) — and the connection stays open; a line from which no id can be lifted is framing corruption and closes the connection.
- **Every dispatch task races the shutdown token.** The task selects (biased) between `ShutdownHandle::cancelled()` and the handler, so a request already in flight when the runtime stops answers `shutting_down` instead of running to its own timeout.
- **Ordered input queue is a fair `tokio::sync::Mutex` per session.** Input methods may expand into several compositor commands (`click` = move + down + up); the queue guarantees submission order per connection without serializing the whole connection.
- **§5.5 `window_id` never reaches the compositor.** `RuntimeCommand::PointerMove`/`PointerButton`/`PointerAxis`/`KeyEvent` carry only their payload plus `reply`; the handler uses `window_id` for four things: (1) resolve window-relative coordinates from `QueryState` window geometry (`input.rs::window_rect`), (2) `record_action` on the observer, (3) for keyboard methods, activate the window first when `snapshot.keyboard_focus.or(snapshot.active_window_id) != Some(window_id)` (`input.rs::activate_if_needed` → `RuntimeCommand::ActivateWindow`), (4) label an `unknown_window` failure. Pointer methods never activate: the compositor delivers buttons/axes at the current pointer position, so the preceding `PointerMove` must land inside the target window's surface. Both the coordinate lookup and `activate_if_needed` validate the window *before* any compositor command, so an unknown id injects nothing.
- **`ErrorPayload.data` is attached only for the three lookup failures that name an id** (observer `UnknownWindow`/`UnknownAction`, registry `UnknownApp`). The compositor-path `unknown_window` — every §5.5 input method, `get_window`, `activate_window`, `close_window`, `capture_*` — carries `code` + `message` only (`error.rs::payload`).
- **`InspectionSource` is synchronous, the runtime is not.** `adesk-inspector` requires a cheap, non-blocking `inspection_input()`; the server therefore keeps an `InspectionCache` and refreshes it asynchronously (`inspection::refresh` renders the full output and issues `QueryState`) immediately before each `inspect_*` frame. Overlays are composited at full resolution and cropped/downscaled afterwards.
- **`translate.rs` owns every cross-crate conversion** (`StateSnapshot`, `Condition`, `ActionKind`, `RendererName`, `Position` → `Point`, `Observation` + image → `ObserveResult`). This is deliberate: it is the single file to change if a sibling changes shape, and it documents the mismatches rather than hiding them. The `Observation` bridges are pure pairings/mappings — the server never rewrites `timed_out`, `quiet` or the resolved condition before responding.
- **Server-synthesized events reserve their `seq` from the compositor.** `dispatch::windows::reserve_seq(&ServerContext)` sends `RuntimeCommand::ReserveSeq` and returns the next number from the compositor's central counter without emitting an event; it is the only `seq` source for `launch_app`'s `AppLaunched` (`dispatch/apps.rs`), each `inspect_frame` push (`dispatch/inspect.rs::render_frame`) and each viewer frame (`viewer/backend.rs::render_frame`), one reservation per emission — the `QueryState` watermark is never used as a stamp. This keeps a single global monotonic `seq` domain across compositor- and server-emitted events (protocol §1): gaps are allowed (spawn failure, dropped/throttled frame), reuse never. `ts_ms` keeps its existing source at both sites (compositor snapshot clock for `AppLaunched`, inspection snapshot for the frame). `./tests/sequence.rs` proves the interleaving by bracketing both emission sites with out-of-band `ReserveSeq` probes.
- **Lag handling is `QueryState` + `resync`, not best-effort patching.** On `broadcast::error::RecvError::Lagged(n)` the pump issues `QueryState`, translates the snapshot and calls `ObserverService::resync`, which marks affected windows uncertain (`docs/architecture.md` §2).
- **Shutdown token is a `tokio::sync::watch<bool>`**, so `cancelled()` cannot miss an already-flagged shutdown (no `Notify` registration race) and `initiate()` is idempotent.
- **Socket lifecycle is RAII + explicit**: `SocketListener::drop` unlinks the socket file only while the path still holds the `(device, inode)` pair it bound, so a successor runtime that rebound the same path keeps its socket; `shutdown::run` removes the file so it is gone before `wait()` resolves. A live socket is never clobbered (`prepare_socket_path` probes with a connect).
- **`adesk-render` is a direct dependency** (`ServerError::Render(#[from] adesk_render::RenderError)`; `images::encode`'s error path; and the PNG encoder itself, since `images::encode_png` delegates to `adesk_render::encode_png` — the workspace's single PNG encoder — after a cheap buffer-shape check); dispatch otherwise reaches rendering through the compositor handle.
- **The two registries share one private generic `Registry<T>`.** `SubscriptionRegistry` and `InspectRegistry` differ only in their payload type, so the storage, id allocation and lock discipline live in `Registry<T>` (over a private `RegistryEntry` trait) once; each wrapper adds only its `subscribe` constructor and its payload accessor, and `InspectRegistry` adds the lock-and-scan `contains`/`prune_closed` probes.
- **The compositor-command seam is one shared `dispatch::command` helper, with the dropped-reply policy injected.** `send_infallible`/`send_result` own the channel/send/await/classify boilerplate used by `windows.rs`/`capture.rs`/`input.rs`; a dropped reply's `ServerError` is a caller-supplied closure because the classification is deliberately non-uniform (seat/state helpers report `shutting_down`; `activate_window`/`close_window`/`render_window` report `internal`).
- **`serde_json` is a direct dependency** (beyond the objective's list) because `ErrorPayload::with_data` carries structured error data (e.g. `{"window_id": 99}`) and `ResultPayload` wraps `serde_json::Value`. `serde` itself is not a direct dependency: the server never derives its own wire types.
- **The event pump is the matching half of the launch → window correlation.** `launch_app` records the `LaunchRecord` *and* sends `RuntimeCommand::NoteLaunch` to the compositor (best-effort, after the successful spawn); `event_pump::correlate_window` feeds a `WindowCreated` with `launch_id: None` to `Correlator::correlate` as a `WindowCandidate` (window id, pid, app_id, title) and hands the *same* stamped event to the observer, the inspection cache and the fan-out, so all three agree. It returns a `Cow`: only a correlated `WindowCreated` is cloned. Uncorrelated windows pass through untouched (never guessed), events that already carry a `launch_id` (e.g. the ones the compositor stamped itself) are never re-correlated, and the lock is poison-recovering. This projects a server-side verdict onto the AGP/observer view; the compositor stamps its own broadcast through its launch ledger.

- **The viewer endpoint is a second transport over the same runtime state, not a second runtime.** `./src/viewer/` owns only the `ViewerBackend` impl and the sockets; the VAP wire types, the codec, `ViewerServer` and the per-connection session stay in `adesk-viewer-proto` / `adesk-viewer`. Frames come from `inspection::refresh` + `images::encode_png`, state from `dispatch::windows::state`, and input from the widened `pub(crate)` `dispatch::input` helpers — nothing is re-implemented.
- **Viewer input targets the active window.** VAP carries no `window_id`, so `apply_input` resolves `snapshot.keyboard_focus.or(snapshot.active_window_id)` — exactly the window the compositor's `inject_*` would resolve against — and maps the normalized output fraction onto it with `dispatch::input::output_fraction_position` (window model, never constants). No window ⇒ `invalid_request("no window is active")`, never a panic and never a silent drop; keyboard input activates the target first, pointer input never does (`activate_if_needed` + the preceding `PointerMove` rule of §5.5).
- **A viewer frame's `seq` is reserved, not observed.** `render_frame` takes its `seq` from `dispatch::windows::reserve_seq`, so compositor events, `AppLaunched`, `inspect_frame` and viewer frames share one global monotonic domain (gaps allowed, reuse never); the `QueryState` watermark is never used as a stamp.
- **One `ViewerServer` and one `ViewerBackendImpl` per runtime, one accept loop per transport.** The backend owns the single `ChangeSignal` (fed by one background pump on `CompositorHandle::subscribe()`: `SurfaceCommit`/`WindowActivated`/`WindowCreated`/`WindowDestroyed`/`TitleChanged` notify, `Lagged` notifies conservatively, `Closed`/shutdown exits), the advisory `ControlOwner` and the `InputQueue` that keeps viewer input in submission order.
- **The viewer accept loops never own teardown.** They select on the shutdown token and stop accepting; only the AGP accept loop calls `shutdown::run`, which removes both socket files. `SocketListener`'s RAII drop (keyed on the `(device, inode)` pair) is the fallback, so a successor runtime on the same path keeps its socket.
- **Binding happens in `Server::start`, TCP is strictly opt-in.** The Unix socket is bound (and the TCP listener, when `--viewer-tcp` is given) before `start` returns; the default path is the AGP socket's sibling, so both endpoints travel together everywhere. A viewer bind failure fails startup with `ServerError::Io` rather than silently serving no viewer.

## Sibling integration notes (contracts the server must satisfy)

- **adesk-compositor**: `spawn` is sync; `wait_ready()` is async and cached; result-bearing `RuntimeCommand`s carry `oneshot::Sender<adesk_core::Result<..>>`; `QueryState` is infallible; `NoteLaunch` acknowledges `()` and is best-effort (`launch_app` logs a failure and still returns the launch); `ReserveSeq` replies the next `seq` infallibly (`u64`; a dropped reply means the thread is gone ⇒ `shutting_down`) and is the server's only source of `seq` for events it synthesizes itself (`AppLaunched`, `inspect_frame`, viewer frames) — the compositor's counter advances without emitting, so a later compositor event can never reuse a reserved number (gaps allowed, reuse not). `StateSnapshot` is `adesk_compositor::StateSnapshot`, which is **not** the observer's snapshot — bridge via `translate::observer_snapshot`.
- **`ActivateWindow`'s oneshot reply is a full activation barrier.** The compositor resolves it only after the WM active window, the seat's keyboard focus and the data-device focus (the gate for `wl_data_device.set_selection`) are applied, and after `WindowActivated` + `FocusChanged` are broadcast; commands are processed FIFO one-at-a-time on the compositor thread, and client sockets are flushed right after the reply in the same calloop callback. `dispatch::windows::activate_window` awaits that reply before the AGP response is built (`connection.rs` writes it to the socket only after `dispatch` resolves), so an awaited `activate_window` response means activation is fully applied. The guarantee covers an *awaited* response only: non-input requests are dispatched concurrently per connection (`MAX_IN_FLIGHT_REQUESTS = 64`), and per-connection execution order is enforced only for §5.5 input methods via `Session::input()`. `docs/protocol.md` §5.3 states this timing normatively: an awaited response means the activation is in force and no follow-up barrier request is needed, while the guarantee stops at the Wayland side (`wl_keyboard.enter`/`leave` and `wl_data_device.selection` reach the affected clients on their own connections; observing the application's reaction stays the agent's job via `observe`/`wait_for_change`).
- **adesk-observer**: record the action before the command; `resync` after lag; waits return observations (timeouts are not errors); `Err(UnknownWindow)` → `unknown_window`, `Err(UnknownAction)` → `invalid_request`; render images *after* the wait; `ActionKind::as_str()` is the AGP method name; a wait whose condition is not `Quiet` carries no per-request quiet threshold, so its `quiet` evidence flag uses the observer's `DEFAULT_QUIET_MS` constant (250, `adesk_observer::DEFAULT_QUIET_MS`) rather than any per-request or configurable value.
- **adesk-app-registry**: registry and correlator must share one `Arc<dyn Clock>`; after a successful `launch` emit `AppLaunched {launch_id, app_id, pid}` on the compositor's broadcast and `correlator.record_launch(record, &app_info)`; the pump then correlates each `WindowCreated` that lacks a `launch_id` (`Correlated` → stamp `launch_id` on the projected event; `Uncorrelated` → pass through, never guess); `scan()` is blocking; child reaping is the server's job; set `WAYLAND_DISPLAY`/`XDG_RUNTIME_DIR` on launches via `LaunchEnv`.
- **adesk-inspector**: implement `InspectionSource` (done by `InspectionCache`); full-output render before overlays; `inspect_capture` = `Inspector::new(overlays).render_request(input, request)` then PNG; `inspect_subscribe` = same per frame, throttled, one `Inspector` per subscription; map inspector errors with `adesk_core::Error::from`.
- **adesk-proto**: `ObserveResult` serializes as `{"observation": {..., "image": ...}}`; `ImagePayload::from_rgba8`/`from_png` are the only constructors; `Method::from_parts` is the decode entry point; defaults (`timeout_ms=5000`, `quiet_ms=250`, `observe.include_image=true`, waits `false`, `format=png`) are the proto crate's, the server must not redefine them.
- **adesk-client**: `ping` validates `protocol_version` (report `PROTOCOL_VERSION` exactly); error responses must not close the connection; waits never attach pixels unless `include_image` is set; its `default_socket_path()` chain matches this crate's exactly.

## Known Issues

- **Signal handlers are installed by `Server::start`**, including in test processes; repeated installation is harmless (`tokio::signal` supports multiple listeners), but tests must not send SIGINT to the test runner.
- **Window-creating AGP E2E is not covered by `./tests/`**: the AGP suites run against an empty runtime (no Wayland client connects), so tiling, focus transitions and AGP input delivery are not exercised there; that coverage lives in the `adesk-testkit` and `adesk-agent` suites. `./tests/viewer.rs` is the local exception — it maps a real toplevel for the viewer input case. Launch correlation *is* covered here by injecting a synthetic `WindowCreated` into the compositor's broadcast.
- **A `quiet` event subscription is accepted but never delivers.** `subscribe_events` accepts `quiet` (only `inspect_frame` fails `EventKind::is_subscribable()`), yet no quiet frame is ever produced: the pump fans out `RuntimeEvent`s only, `SubscriptionRegistry::fan_out` filters with `EventKind::matches`, which never matches `Quiet`, and no code path constructs `EventPayload::Quiet` (the only server-synthesized event kind is `inspect_frame`, `dispatch/inspect.rs`). This matches `docs/protocol.md` §5.6 (no v1 emitter; quietness is pull-style via `wait_for_quiet`/`observe`). Pinned by the unit test `subscriptions::tests::protocol_only_kinds_never_match_runtime_events`; no E2E in `./tests/` covers a quiet subscription.
- **No E2E case in `./tests/` exercises a *successful* AGP §5.5 injection**: every AGP input call here fails by design (unknown window, or no keyboard focus when `window_id` is absent); delivered AGP input is exercised by the `adesk-testkit` / `adesk-agent` E2E suites, where a Wayland client connects. (`./tests/viewer.rs` does deliver input successfully, but over VAP, not §5.5.)
- **An ended `inspect_subscribe` stream is not announced on the wire.** §5.7 has no termination event, so a client whose stream stopped (render failure, `unsubscribe_events`, a closed connection) sees the `inspect_frame` frames stop rather than a message. The runtime side stays coherent: `dispatch/inspect.rs::inspect_loop` deregisters its own `InspectRegistry` entry before returning, and `event_pump::prune_inspect_streams` covers connections that die without unwinding their tasks — no stale entry claims a live stream.

- **The viewer endpoint is enabled by default.** Every `Server::start` therefore needs a writable parent directory for `…/adesk-viewer.sock` in addition to the AGP socket path, and every in-process test runtime binds one. `adesk-testkit`'s harness is unaffected (its temp `XDG_RUNTIME_DIR` makes the sibling path private), and `--no-viewer` / `without_viewer()` opts out.
- **The opt-in TCP transport carries no authentication.** VAP v1 has no auth and the handshake's `ControlOwner` is advisory, so an exposed `--viewer-tcp` listener accepts any client that can reach the address. Only bind it on a trusted interface.
- **Viewer coverage gaps in `./tests/viewer.rs`**: the TCP transport, viewer `scroll`/`text`, the `frames()` push loop, `set_control` and multi-connection fan-out have no E2E case. Only the default Unix socket path is exercised.
- **The outbound-sink registry is process-global but keyed by a per-runtime id.** `dispatch::session_sinks()` is a `static OnceLock<Mutex<HashMap<SessionId, EventSink>>>` while `SessionId` comes from `ServerContext::next_connection_id` — a counter recreated per runtime and starting at `1`. Two runtimes alive in one process would collide on the id and cross-wire their subscription frames; `./tests/common/mod.rs` deliberately forbids two live `TestRuntime`s in one test because of this.
- **A viewer input with no active toplevel is answered with a VAP `error`, not an `input_ack`.** `apply_input` needs a window (VAP carries no `window_id`), so on a runtime with no mapped toplevel every input fails `invalid_request` while the connection stays open — `tests/viewer.rs` pins exactly that, and the delivered-input case drives a real Wayland toplevel.

## Hot Paths (performance)

Cost paid on **every** request / event / frame, per location (no benchmarks exist in the repo).
At the default 1280x800 output the full-output `ImageBuffer` is ~4 MB, so each full-frame copy below is a 4 MB memcpy plus a 4 MB allocation.

- `subscriptions.rs::fan_out` (line 249) holds the registry `Mutex` across the kind match, the `Frame::clone()` (a deep payload copy, e.g. the damage `Region`) and the `try_send` of every matching subscriber.
- `connection.rs::read_loop` (line 222) spawns a task and clones `Dispatcher`/`Session`/`ConnectionWriter`/`ShutdownHandle` per request.
- Every §5.5 method pays an extra compositor round trip for a full `QueryState` (`input.rs::window_rect` line 319, `activate_if_needed` line 433 — each clones every `WindowInfo`); `type_text` costs 1 + N round trips for N characters.
- `viewer/backend.rs::render_frame` (lines 183-207) re-renders the whole output, stores a full-frame clone, PNG-encodes and base64-encodes it (`ImagePayload::data` is a base64 `String`) and reserves a `seq`, per frame; `apply_input` (line 219) takes a full `QueryState` per input.
- The viewer change pump (`viewer/backend.rs:76`) takes its own `CompositorHandle::subscribe()`, so every `RuntimeEvent` is cloned once per broadcast receiver (server pump + change pump).
- `inspection.rs::inspection_input` (line 145) pays one full-frame copy because `adesk_inspector::InspectionInput` needs an owned `ImageBuffer`; this copy is inherent, not reducible.
- Wire-codec costs owned by `adesk-proto` (report upstream, never patch a sibling from here): `NdjsonCodec::decode_str` parses to a `serde_json::Value` DOM before `Frame::from_value` (`codec.rs:58`), `request_from_value` deep-clones the params subtree (`frame.rs:440`) and `decode_params` then runs `from_value`; `EventFrame::serialize` builds an intermediate `Value` per frame per subscriber (`frame.rs:289` via `event.rs:474`).

## Test Strategy

- **Unit level (in-module):** `config::parse_size/parse_renderer/default_socket_path`, `translate` (every bridge, both directions), `images::encode`/`encode_png` (png/rgba8/scale, padded and trailing-byte buffers, and the `encode_png` byte-identity check against `adesk_render::encode_png`), `subscriptions` (id allocation, filtering, removal on disconnect, `contains`/`prune_closed`), `session::InputQueue` (FIFO) and the `#[cfg(test)]` `Session::subscriptions` accessor, `shutdown::ShutdownHandle` (idempotence, `cancelled`), `inspection::InspectionCache`, `error` (compositor/proto mapping tables), `socket::SocketFileId` (drop identity check), `connection::request_id_from_line`, `event_pump::correlate_window` (stamping, pass-through, no re-correlation, other event kinds, poisoned lock), `config::viewer_socket_sibling`/`viewer_socket_path` and the `src/main.rs` viewer CLI mapping (viewer on by default, `--viewer-socket`, `--viewer-tcp`, `--no-viewer` wins); `cargo test -p adesk-server --lib` is green.
- **E2E level (`./tests/`, ten integration targets, 67 tests):** `common::TestRuntime` starts one real runtime per test (`Server::start`) on a private temp socket with the pixman renderer, driven through `adesk-client` and the raw NDJSON `RawClient`; `./tests/inspector.rs` also drives the §5.7 push loop into its terminal failure by stopping the compositor out-of-band and asserts the stream deregisters itself; `sequence.rs` brackets both server-synthesized `seq` emission sites with out-of-band `ReserveSeq` probes to prove the single global `seq` domain; full plan in `./tests/CONTEXT.md`. No test may require a display, GPU, network or installed application (`subscriptions.rs`'s launch fixture spawns `true` from `PATH`).
- **Viewer level (`./tests/viewer.rs`, 9 tests):** the only suite with a Wayland client — `adesk-testkit` is a `[dev-dependencies]` entry for exactly this reason (the same dev-dependency cycle `crates/adesk-compositor` already uses), so the suite maps a real toplevel, activates it over AGP and proves a viewer `pointer_button` and a `Ctrl+C` chord each answer an `input_ack` carrying a real `ActionId` **and** reach the seat (the test client observes the pointer press and every chord press/release in its own event history). With two real toplevels mapped, `activate_window` is proven runtime-native: activating the non-active window answers an `input_ack` with a real `ActionId` and the next `state` reports it active; activating an unknown id answers a VAP `error` with code `unknown_window` and keeps the connection. Also covers the handshake (protocol version, output, renderer), a full-output frame with a strictly increasing reserved `seq`, `request_state`, `without_viewer`, viewer-socket removal + rebind, and an undeliverable input answered with a VAP `error` that keeps the connection open. No sleeps: every wait is deadline-bounded.
- **The §5.4 image-*present* branch is not covered by the AGP suites.** No AGP suite here connects a Wayland client (only `./tests/viewer.rs` does), so `observe` with `include_image = true` can only reach the no-candidate branch, which `observation.rs` pins end to end (both through the SDK and on the wire: an explicit `null` image, never a `render_failed`). The rendering half — a window that has committed a buffer — needs a real Wayland client, so it is covered by `crates/adesk-testkit/tests/e2e_launch_observe.rs` (a window-scoped `observe(quiet)` at the protocol-default `include_image = true` decodes to the tiled rect and matches the client's fill pattern).
- **Validation commands (always through the dev shell):** `./scripts/dev.sh cargo check -p adesk-server --all-targets`, `./scripts/dev.sh cargo test -p adesk-server`, `./scripts/dev.sh cargo clippy -p adesk-server --all-targets --no-deps -- -D warnings`, `./scripts/dev.sh cargo doc -p adesk-server --no-deps` — all warning-free.

## Notes for Agents

- **Public items with no caller anywhere in the workspace** (verified with workspace-wide `rg`; they are shipped library API, so removal is a judgement call, not a bug fix): `Dispatcher::context` (`src/dispatch/mod.rs:74`), and `impl From<ServerError> for adesk_core::Error` (`src/error.rs:125`, exercised only by its own unit tests).
- **Test-only accessors** (no production caller): `Session::subscriptions` (`#[cfg(test)]`, `src/session.rs:65`), `ShutdownHandle::default`, `RunningServer::shutdown_handle`.
- **`image` is a runtime dependency used only under `#[cfg(test)]`** now that PNG encoding is delegated to `adesk_render` (only `src/images.rs`'s PNG decode helpers touch it); moving it to `[dev-dependencies]` is a possible cleanup.
- **Directory-scan check before adding a `pub fn`:** every module is declared in `src/lib.rs`; `src/viewer/` exposes only `pub(crate)` items behind a `pub mod`, so it could be `pub(crate) mod viewer`.

- **Reusable seams for a second (non-AGP) endpoint.** `src/images.rs::encode`/`encode_png` is the only `ImageBuffer` → `adesk_proto::ImagePayload` encoder; `src/inspection.rs::refresh` renders the full output (`RuntimeCommand::RenderOutput`) and returns an `InspectionSnapshot` (`frame`, `active`, `cursor`, `seq`, `ts_ms`). The §5.5 seat helpers live in `src/dispatch/input.rs` and are `pub(crate)`: `move_pointer`, `move_to`, `button_event`, `click_times`, `send_unit`, `activate_if_needed`, `window_rect`, `type_character` take `&ServerContext`, and `resolve_pointer_position`, `is_unmappable_key` and `output_fraction_position` are pure. `dispatch::windows::{state, reserve_seq, command_error, unknown_window}` are `pub(crate)`. `SocketListener` is a generic Unix-socket binder (RAII unlink keyed on the `(device, inode)` pair); `shutdown::run` removes the AGP socket file **and** the viewer socket file; `event_pump` is the runtime's event-broadcast reader (`CompositorHandle::subscribe()` can be taken independently by any task). `./src/viewer/` is the canonical second consumer of all of these — a further transport should follow its shape (implement the sibling crate's backend trait over `ServerContext`, bind before returning, never own teardown) instead of copying any of it.
- Do not add AGP methods or fields outside `docs/protocol.md`; the dispatcher must stay total over `adesk_proto::Method`.
- Keep the public API stable: `adesk-testkit` and `adesk-agent` are written against it. If a change is unavoidable, report it to the parent instead of editing siblings.
- The crate has no blanket `allow` attributes: keep `clippy -D warnings` and `cargo doc` clean without adding new ones.
